  scripts/build-uboot-source.sh

布局
----
SRAM 0x40000：96 字节 eGON 头；0x40060：SPL 入口。
SPL 本体、BSS、附加 DT 均低于 0x5e000。
初始栈 0x66000，早期堆 16 KiB，并为栈/GD 留足空间。
FEL thunk 0x66a00，BootROM 保存区 0x66c00..0x67fff，不覆盖它们。
U-Boot proper 入口 0x4a000000；内核 FIT 暂存 0x50000000。
SD 候选引导区的起点对应整盘 8 KiB；其中 proper 对应整盘 128 KiB。
SPL 只接受普通 SD0/eMMC2 启动源，暂不支持高偏移或 SPI NAND/NOR。
U-Boot 自身 SD/eMMC 写入和 saveenv 关闭；3 秒后自动运行来源对应脚本。
FEL 读取 header 指定的 0x4f100000 脚本；存储启动读取第一分区 boot.scr。

最后硬件验证时使用的路径（现在不需要接板）
----------------------------------------
先进入 SoC 原生 FEL，从 SRAM SPL 开始；不能从已经运行的厂商 U-Boot
直接跳到这份 SPL，因为它会重新训练并破坏整个 DDR 的内容。
参考工具固定为 dlan17/sunxi-tools 提交：
660d7e08edd025c8f84ab8eba3d8a903a5b81ae0（T153 RFC #252）。
本地补丁将 USB 等待上限设为 180 秒，以允许软件 DDR 眼图训练。

未来验证命令模板（没有在本次执行）：
  FEL=./u-boot-work/sunxi-tools-660d7e08edd025c8f84ab8eba3d8a903a5b81ae0/sunxi-fel
  sudo "$FEL" uboot artifacts/t153-uboot-2026.07-source-fel.bin \
      write 0x50000000 artifacts/实际的OpenWrt-initramfs-kernel.bin

观察 UART0 PB9/PB10，115200；DDR 成功返回 FEL 后才会上传 proper 和内核。
进入 T153-SOURCE=> 后执行：
  bootm 0x50000000
U-Boot 会移除不存在的厂商 PSCI 服务并禁用 CPU1..3，明确显示单核限制。
已新增整盘镜像和显式 eMMC 安装器；完整步骤见 FLASH-SOURCE.txt。
上述手动 FEL 命令没有上传脚本，会停在提示符；推荐新的
  sudo scripts/boot-fel-installer.sh --boot
它只上传 RAM 并启动安装系统，不自动写盘。
DDR 训练、FEL 返回、MMC 加载、Linux/网络等实际结果均须最后上板记录。

T153 FEL header 交接补充：thunk 返回后将 SPL 头从 0x40000 换到 0x66c00。
主机工具按 swap 表找到返回后的头，U-Boot 从 0x66c00 接收脚本地址；
冷启动仍读 0x40000。未知启动来源停在提示符，不自动启动磁盘。
